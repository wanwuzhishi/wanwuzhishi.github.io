文章与草稿

「文章」页管理两类内容：

类型 存放位置 说明
正式文章 source/_posts/ 会被生成到博客里
草稿 source/_drafts/ 不会出现在博客，写好后可一键转为正式

列表里每篇文章显示标题、状态、路径、日期、标签、分类、字数。点标题或「编辑」进入编辑器。

草稿转正式：在编辑器顶部点「转为正式文章」，文件会从 _drafts/ 移到 _posts/。

删除：删除的文章会移入系统回收站，可以恢复；误删了去回收站找回来即可。

编辑器工具栏

编辑器顶部有两行格式化工具栏：

第一行：标题（H1–H4）、加粗、斜体、代码块、引用、有序列表、无序列表、任务列表

第二行：链接、图片、表格、分割线、清除格式、撤销、重做、＋（自定义片段）

选中文本后点对应按钮即可套用格式。所有按钮都有中文悬停提示。

自定义插入片段

写文章时常要重复输入同样的内容 —— 版权声明、更新时间、标准结尾。第二行末尾的「＋」可以把这些做成一键插入的按钮：

  1. 点「＋」打开「自定义插入片段」
  2. 填按钮名称（限 6 字，如「版权」「更新」）与要插入的内容
  3. 添加后工具栏立刻出现该按钮，写文章时点一下即插入光标处

内容支持 {{date}} 占位符，插入时自动替换为当天日期 —— 适合做「本文更新于 2026-01-01」这类模板。

片段的编辑与删除都在同一个弹窗里完成。它是全局共用的（不像文集和参数定义按站点隔离），因为版权声明这类内容换站点时通常也要用。

图片处理

三种方式都能插图，都会自动保存到站点 source/images/ 并插入正确的 Markdown 链接：

  1. 直接粘贴 —— 截图后 Ctrl+V 即插入
  2. 拖拽 —— 把图片文件拖进编辑区
  3. 选择文件 —— 用工具栏的图片按钮浏览选择

图片文件名会自动处理（空格转连字符、加时间戳去重），避免中文名导致的路径问题。

自动保存与分栏预览

  • 自动保存：停止输入后自动存盘，延迟可在「设置 → 应用」调整（0.5–10 秒）
  • 分栏预览：编辑器右侧实时渲染 Markdown 效果，开关状态会记住
  • Ctrl+F：在正文中查找替换
  • 状态栏：底部显示字数与保存状态（有未保存改动时会提示）

全文搜索

「文章」页顶部的搜索框支持全文检索：

  • 搜标题、标签、分类 —— 立即匹配
  • 搜正文 —— 稍等片刻，命中结果会显示上下文摘录

文章参数

编辑器右侧的「文章参数」侧栏（默认收起，点顶部按钮展开）包含：

分类与标签 —— 输入后回车即可新建，支持多级分类。

自定义参数 —— 给文章加任意 front-matter 字段。参数有三种类型：

类型 界面形态 写入方式
键值式 文本输入框 原样写入字符串
开关式 可勾选的方框 勾选/取消写入你指定的值
结构化 YAML 编辑框（语法高亮） 支持嵌套对象与对象数组

添加参数时可以选择类型、填中文显示名与英文键名。开关式还能自定义选中/取消时写入的值（默认 true / false）。

关于开关式参数：写入的 true / false 是 YAML 布尔值而不是字符串。这点很重要 —— 字符串 'false' 在主题模板里会被当成真值，导致开关失效。

结构化参数：写资源卡这类复杂字段

游戏资源、网盘分享类文章常有这样的 front-matter —— 一个 resource 键，里面既有标量字段，又有多条下载链接：

这种嵌套结构用普通文本输入框写不了（会被压成字符串而丢失数据），所以「结构化」类型提供一个带语法高亮的 YAML 编辑框，直接写或粘贴即可。

模板一键套用：点参数卡片上的「模板」按钮，内置 5 个骨架可选 ——

模板 内容
游戏资源卡 资源信息 + 多网盘链接（含版本、平台、大小）
多网盘链接 只有下载链接列表
更新日志 多版本更新记录（版本号 / 日期 / 变更项）
视频嵌入 视频地址 / 封面 / 作者
图片画廊 多张图 + 说明文字

点一下即填入，改值就行。也可以把当前填好的内容存为自己的模板，下次直接套用。

自动识别：打开已有文章时，只要某个字段的值是嵌套对象或对象数组，就会自动按结构化类型处理 —— 不用手动改类型，也不会被写坏。

语法校验：YAML 写错时输入框标红、暂停自动保存并在状态栏提示，不会把坏数据写进文件。

小提示：提取码、验证码这类值建议加引号（password: "1234"）。YAML 规范里裸写的 1234 会被解析成数字，加引号才是字符串 —— 否则某些主题模板做字符串比较时会出错。

参数定义按站点记忆：在 A 站配置的参数不会跑到 B 站；同一站点里，新文章会自动带上本站在用的参数名，你只需要逐篇填值。

其他元数据

侧栏底部还有「其他元数据」区域，只读展示 front-matter 里的其余字段（比如主题注入的 layout、comments），避免误改这些由主题或插件控制的键。
