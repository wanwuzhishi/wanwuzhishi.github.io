返回 使用指南总览

基础配置

「设置 → 基础配置」以表单形式管理 _config.yml 的常用项：

站点标题、副标题、描述、作者、语言、时区、网站 URL、根路径、永久链接格式、每页文章数、文章资源文件夹。

也可以在这里设置站点图标 —— 选一张图片（支持 ico / png / jpg / svg / webp），也可以直接把图片拖到左侧方块上。

图标会写入站点 source/favicon.*，所以 Hexo 生成后你的网站也会用上这个图标 —— 不只是应用里显示。

写入安全性

保存配置时，HexoDeck 采用行级替换：

  • 只改动目标键所在的那一行
  • 注释、空行、键的顺序全部原样保留
  • 保存前做 YAML 语法校验，写坏文件会被拦下
  • 首次修改自动备份为 _config.yml.hexodeck.bak

所以可以放心用 ── 你的配置注释不会丢。

高级：直接编辑配置文件

「设置 → 高级」提供 _config.yml 的原文编辑：

  • YAML 语法高亮
  • Ctrl+F 查找替换
  • 保存前语法校验

适合表单没覆盖的字段，或者某些插件的个性化配置。

配置文件路径需要你指定

应用不会自动定位配置文件。第一次打开「高级」页时，会弹窗让你指定要编辑的 _config.yml：

  • 浏览选择 —— 自己挑文件
  • 使用默认位置 —— 一键采用站点根的 _config.yml

指定后会按站点记住，之后再打开不再询问。想换文件，点面板头部的「自定义路径」；想清空记忆重新询问，在弹窗里点「清除记录」。

这样设计是为了避免误改 —— 有些项目会用 _config.xxx.yml 之类的多配置结构，自动定位可能改错文件。

部署配置

「设置 → 部署」配置推送到哪里：

字段 说明
部署方式 Git（GitHub Pages 等）或「不部署（仅本地）」
仓库地址 如 https://github.com/用户名/用户名.github.io.git
分支 一般是 main；旁边有 main / master 快捷填入按钮

配置不完整会提前提示：

  • 分支为空 → 明确警告（空分支会导致 git 推送失败）
  • 仓库地址缺 .git 后缀 → 建议补全
  • 未安装 hexo-deployer-git → 提供「一键安装」按钮

主题管理

「设置 → 主题」集中管理主题。

从压缩包安装

把主题压缩包拖进窗口，或点「浏览文件」选择。支持格式：

.zip / .tar / .tar.gz / .tgz

解压后应用会自动识别主题目录（判断依据是含 _config.yml 或 layout/），并规整到站点的 themes/ 目录 —— 单层或多层包裹都会自动处理，不会出现 themes/xxx/xxx 这种嵌套。

同名目录会被拒绝，避免覆盖你已有的主题。

主题列表

列出所有已安装主题（检测 themes/ 目录 + npm 包 hexo-theme-*），点「一键切换」即可更换。切换后预览会自动重启。

主题配置

主题配置文件同样不自动定位 —— 第一次编辑某个主题的配置时会弹窗让你指定：

  • 可以是站点根的覆盖文件（_config.主题名.yml，推荐做法）
  • 也可以是主题自带的配置（themes/主题名/_config.yml）

路径按「站点 + 主题」分别记忆 —— 换主题后各自有各自的配置路径，不会混。

编辑器带 YAML 语法高亮，保存前做语法校验。

主题市场

内置 8 款热门主题，点「安装」即通过 npm 装到站点里：

Butterfly、NexT、Fluid、Shoka、Stellar、安知鱼、Keep、Volantis

插件管理

「设置 → 插件」列出站点 package.json 里的所有 hexo-* 依赖：

  • 显示版本号与中文说明
  • 安装 —— 输入包名（如 hexo-generator-feed）点安装
  • 卸载 —— 带二次确认（渲染器类插件卸载后站点可能无法生成，会特别提醒）
  • 设置 —— 点击直达该插件在配置文件里的配置键位置

底部的「插件配置键」区域可以搜索插件名 / 配置键 / 说明，点击即可在配置文件里定位或插入配置模板。

插件安装 / 卸载需要本机有 Node.js。
