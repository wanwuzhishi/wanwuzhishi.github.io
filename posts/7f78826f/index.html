左栏组件

个人名片

外观类配置项

配置项 说明 默认值
avatar 头像图片路径 主题自带占位头像
avatar_size 头像直径，接受 72px 这类带单位值，或直接写数字 72（按 px 处理） 64px
title 头像下方的主标题（如昵称、站名） 空
title_icon 主标题左侧的小图标，常配站点 favicon 使用 空
badge 头像右下角角标文字 不显示
badge_title 角标的鼠标悬停提示 空
bio 简介文字；写成 bio: false 或留空可整段隐藏 取站点 description
social_title 社交图标区上方的小标题 空
icon_size 社交图标直径（数字，按 px 处理） 19

社交链接

  • social[].name 决定图标，可用：github / bilibili / telegram / mail / rss / link。
  • social[].title 同时作为图标的 title 与无障碍标签，鼠标悬停可见。
  • avatar 加载失败时会自动回退到主题自带的占位头像。
  • 不写 name 和 bio 时，会回退到站点 _config.yml 的 author 和 description。
  • 想省掉社交区，直接把 social 整体注释掉即可，标题和分隔线会一并隐藏。

头像与角标尺寸用的是 CSS 变量（--avatar-size / --icon-size）实现，因此改动后无需改动任何样式文件。

分类与标签

显示顺序按内容数量从多到少，数量为 0 的分类不会出现。

左栏分类是跟随页面上下文的：

  • 首页、归档页：显示全部分类；
  • 文章页（文章总页、文章详情页、文章分类页）：只显示含有文章的分类；
  • 资源页（资源总页、类型页、资源详情页）：只显示含有资源帖的分类。

这样文章读者不会被资源分类干扰，资源访客也看不到纯文章分类，两侧列表都更短、更聚焦。

入场动画

卡片滚动进入视口时会淡入上移，由 echo.js 里的 IntersectionObserver 实现，默认开启。
想关掉的话，删除 source/js/echo.js 中「Reveal on scroll」那一段即可。

常见问题

菜单点了打不开 / 页面空白

先看终端有没有报错。最常见的原因是模板里引用了不存在的变量，
或者生成器返回的 page.posts 被当成了 Query 对象处理。

重新生成时终端会直接指出出错的文件和行号。

改了配置不生效

分三种情况：

改了什么 需要做什么
themes/echo/_config.yml 重启 hexo server
站点 _config.yml 重启 hexo server
scripts/*.js（生成器） 重启 hexo server
CSS / JS / 模板 一般热更新，必要时强刷（Ctrl+F5）

改了 colors.accent 却没变？主色是在 head.ejs 里注入的，
如果你改的是编译后的 public/css/echo.css，下次生成会被覆盖——
要改就改 themes/echo/_config.yml，然后 hexo clean && hexo generate。

浅色主题下横幅还是原来的深色 / 灰色

自己写浅色覆盖规则时，最容易踩的两个坑：

  1. 选择器优先级不够。主题里深色状态的横幅用的是
    .page-banner.has-banner .page-banner-card（三个 class），
    而 [data-theme='light'] .page-banner-card（一个属性 + 一个 class）压不过它。
    写浅色规则时必须带上 .page-banner / .has-banner 上下文，把优先级提上去。
  2. 横幅大图写在 HTML 内联样式里。.page-banner 的
    style="background-image:url(...)" 是模板输出的内联属性，
    普通 CSS 盖不住，需要在浅色规则里用 background: ... !important 压制。

另外浅色规则要同时照顾两个属性：data-theme（head.ejs 里的运行时 JS 写入）
和 data-theme-hint（layout.ejs 直接输出的配置值，用于 JS 尚未执行时防闪帧）。

验证时如果无头浏览器也跟着系统深色渲染，可以临时做一个强制
data-theme="light" 的验证页截图确认，改完记得删掉。

排查口诀：改完 CSS → hexo clean && hexo generate → 停掉旧 server 换端口重启 → 浏览器强刷。
只改源文件就断定”没生效”是最常见的原因，因为运行中的 server 会一直供旧 CSS。

窄屏展开菜单后白底白字（浅色主题）

如果你是照着上一条 FAQ 给自己写浅色规则时遇到的，八成是踩了同一个坑：
首页 Hero 的导航是透明悬浮在深色大图上的，所以浅色规则会主动排除它
（:not(.has-hero)），让白字保留。可是窄屏展开的抽屉菜单是
自带实底浮层（background: var(--bg-elev)，浅色下为纯白），
它的链接同样继承了白字 —— 于是白底白字。

判断原则：看这个元素自己有没有底色。

  • 有自己的实底（抽屉、卡片、弹窗）→ 文字必须跟随主题色，用 var(--text) / var(--text-soft)
  • 透明悬浮在大图上（首页顶栏）→ 固定用白字，任何主题都一样

资源没出现在资源库

按顺序检查：

  1. front-matter 里 resource.enable 是不是 true
  2. resource.type 的值是否与站点 _config.yml 里 resources.types[].key 一致
  3. 文章文件是否放在 source/_posts/ 下
  4. 有没有执行过 hexo clean

侧栏收起后目录不见了

这是预期行为：右栏在 1280px 以下会收起，
此时目录会转移到正文顶部的可折叠区块，不会丢失。

封面图不显示

  • 确认路径以 / 开头，且文件真实存在于 source/images/ 下。
  • 路径是相对站点 source，不是相对文章文件。
  • 没有封面时卡片会显示渐变占位块，属于正常回退。

导航栏挡住锚点

主题已通过 scroll-padding-top 处理锚点偏移，
滚动到标题时不会贴在导航栏下面。如果你自定义了导航高度，
记得同步调整 --header-h 变量。

发布主题前要清理什么

  • 主题 _config.yml 里的个人信息、头像、社交链接
  • source/images/ 下你自己上传的图片
  • 演示文章（source/_posts/ 里的示例内容）
  • public/ 与 .deploy_git/ 之类的构建产物
